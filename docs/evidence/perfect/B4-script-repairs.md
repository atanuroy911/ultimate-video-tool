# B4: what repairing a director's script changes is told, not done silently

Done on 2026-11-06 (plan decision 1).

## What changed
- `script/validate.py` `repair_script(..., notes=None)`: every repair it makes is also written as a note `{scene, says, meaning}`. `meaning` is True when the repair changed what the director wrote, False when it only filled in the obvious. 35 kinds, each described in plain words with the value it saw:
  - **changed what the director wrote:** an overlay text or an action's bubble, target or prop cut short; an action, overlay or sound moved to another word because its word is not in the scene; an action that is not a verb left out; an action by someone the cast cannot hold given to the first character; an emotion that is not one left as neutral; a wrong side replaced by the verb's default; a camera shot or move removed; a scene's set that is not one of the sets replaced; a set that is not a kind of place made plain; a scene naming a beat that does not exist, a scene with no beat that exists, a beat in no scene (an empty scene added), a beat in two scenes, scenes that cross each other in the beats (every beat becomes its own scene); a sound that is not in the library; an overlay that cannot be kept; the emoji mode removing characters, places, actions and non-emoji overlays.
  - **small things filled in:** a verb or emotion synonym; the default side of `walk_in`, `walk_out` and `turn`; the emotion of `react`; the number of `count`; a place outside the picture moved to the edge; a character added because it acts; a role, head or accessory or colour that is not known; a set used but not declared; a pointed-at prop added to the set; the kind asked for winning over the kind written; highlight words left out; scenes put in beat order.
- `script/service.py` `apply_script`: **strict (Claude or Codex over MCP)** returns every change of meaning as an error, so the director fixes its own script and submits again, and nothing is applied until it does; the small things come back in `repairs`. **Not strict (the local AI, the person's own edit)** applies the script as repaired and returns everything in `repairs`. The MCP tool's description says so.
- `script/repairs.py` (new): `repairer` keeps the notes of the answer finally used (also through the revision round), `record` writes them to Details, Problems: one warning per scene for what changed, one info line for the small things.
- Hooked in: `ai_script` and `revise` (the director stage, `service.direct`), `chat.talk` (the person asks the director for a change), and `apply_script`.

## Checks
`tests/test_script_repairs.py`, 44 checks: one for each kind of repair above (it happens, it is described with the right scene and the right `meaning`, and the repaired script validates), the emoji mode, a script that needs nothing has no notes, `repair_script` without notes as before, a clean script applied with nothing to report, a director told what would have changed and nothing applied, small things in `repairs` with the script applied, the local AI's script with its Details, Problems entry, the MCP tool, the AI script path and the director stage and the chat each keeping and recording the notes.
