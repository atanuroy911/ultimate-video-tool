# K5: every other place that sets a card asks, or says what it chose

## What changed (one function behind each: `gpuassign.change`)
| Place | What it does now |
|---|---|
| `vt gpu allow <cards, all or none>`, MCP `gpu_assignment` | K1. They also restart our own Ollama or ComfyUI when the card they sit on changes (K3). |
| **`vt gpu setup [--gpus ...] [--ask/--no-ask]`** (new) | The question for a terminal. A flag answers it. With two or more cards, nobody answered, and a person at the keyboard, it lists the cards with what uses each and asks. With nobody there it keeps the one-card default and says how to change it. With one card it only says which it uses. A wrong answer stops with a sentence and changes nothing. |
| **`vt server --gpus ...`** | Takes the answer on the command line, saves it, then fences itself (K2). `vt engine run` fences itself too. |
| `install-engine.sh --gpus 1,2` (or `all`, `none`), `install-engine.ps1 -Gpus ...` | Call `vt gpu setup` before anything is installed or started (so an engine is never started on a card that was not chosen). Their help names the flag. |
| Docker | `VT_GPUS` (compose file and `docker-entrypoint.sh`): applied before the engine runs; a wrong value does not stop the container (it says so and starts with one card). `README-ENGINE.txt` has a section "Which graphics cards may Video Tool use" for all of them. |
| **The server's own pages** | New `gpu-choice.js` (served at `/gpu-choice.js`): the same question and answers as the Studio's Server page, for the overview at `/` and Server settings at `/manage` (a new "Graphics cards" tab, opened by itself when a choice is waiting or by `#cards`; the install tab no longer asks for a card for a new install). Plain English, text set with `textContent`, 44 px rows, the keyboard stays on the switch while it redraws, "this server is older than this page" for an old server. |
| **The Electron server window** (`server/desktop`) | `inspect()` reads the cards; the overview has a "Graphics cards" entry (hidden with one card, with an older server, or when stopped) saying which cards may be used or that nobody has chosen, with "Choose graphics cards"; the tray has the same item; the question opens by itself once, the first time (a note in the app's folder). The window's own refresh no longer reloads the settings page (it did not know about the `#cards` tab). |
| **The Linux window** (`server-manager-gtk.py`) | The same entry and tray item, and the question opens by itself once. |

## Found on the way (important)
- **A loop in my own K2 code.** The default card depends on what works on each card; the System panel's reading of the cards asked "which cards may Video Tool use" for its `usable_by_video_tool` flag, which asked for what works on each card, which asked the System panel's reading... In the unanswered state with two cards (exactly the owner's server after an update) one reading made **534 nvidia-smi calls and took minutes**. The fake-nvidia-smi test of this step found it (a reading took 105 s). Fixed twice over: `allowed()` takes the cards and programs the caller has just read, and an asking-from-inside guard returns nothing instead of looping. A reading now takes 4 calls. `tests/test_gpu_setup.py` counts the calls per operation and would fail if it came back.
- nvidia-smi was asked for the same cards many times within one request: its answer is now kept for two seconds (an empty answer, which means "the question failed", is never kept).
- The saved list of cards is kept in the driver's order whatever order it was typed in (it is the order CUDA numbers them).
