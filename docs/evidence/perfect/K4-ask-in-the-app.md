# K4: the question is asked in the app

## What changed
- **`client/studio/src/components/GpuChoice.tsx`** replaces `GpuAssignment.tsx` (deleted). One component, two uses:
  - **Server page** (page mode): "Graphics cards". One row per card: name, free memory, what is using it now in words ("python3 is using 9.7 GB. Ollama is using 1.17 GB." or "Nothing else is using it."), and a switch "Video Tool may use this card" (a real `role="switch"`, named with the card). Each switch saves at once. When nobody has answered, a note says so and which one card is used meanwhile, with "Keep this" to make that the answer. When no card is on, it says Video Tool then works on the processor and that this is much slower. After a change it says programs that were already started keep their old cards until the server is restarted. When two or more cards are on, "Which card does what" appears (primary card, rendering, speech recognition, Video Tool's own language AI, its own picture engine), each choice listing only the cards that are on; with one card on there is nothing to choose, so nothing is shown. Below it, "Programs Video Tool works with" (K3), now translated by the `code` the server sends.
  - **Setup wizard** (setup mode): shown as the second step whenever the server has two or more cards ("Which graphics cards may Video Tool use?"), without a frame or title of its own, with "Use these cards" (saves and moves on) and "Not now" (moves on, keeps the one-card default). `SetupWizard.tsx` no longer has "Graphics card for a new install" or any card of its own; with one card the wizard stays at four steps and asks nothing. `Steps` (the sheet) lets a step build its body from its own Back/Continue so a button inside it can move on.
- **Server side:** `setup.STEPS` has `cards`; `ComfyInstaller` and the setup overview use the card of the "pictures" job instead of `setup_gpu` (`setup.pictures_card()`; nothing new is stored, `PUT /api/setup` still accepts a card number for one install and ignores it for storage); `sysstats.snapshot()["needs_gpu_choice"]` tells the sidebar.
- **The dot:** while `needs_gpu_choice` is true the Server item in the sidebar, and the Server tab on a phone, carry a small accent dot (named "a graphics card choice is waiting" for a screen reader). No banner.
- **Words:** `gpu.*` in English and Bangla (`i18n.ts`); the engine sentences are built from the server's `code` and the card names, so they are Bangla too (card and product names stay as they are). Buttons and rows are 44 px tall on a phone.

## Not done here (and why)
- **A "Restart" button.** The page says in words that a restart is needed. There is no restart endpoint: how a server is supervised differs (the owner's is a systemd user unit with `Restart=on-failure`, the Windows manager has its own Restart button, a terminal run has no supervisor), and a wrong guess would stop a server and not bring it back. It is added to E15 (server page wording): offer it only where the server can tell how it is supervised, and refuse while a job runs.
- The management pages (`management.html`, `engine-management.html`, the server manager window, the GTK window), the install scripts, Docker and the other places that choose a card (K5). `engine-management.js` still sends a card number with an install; the server accepts and no longer stores it.
- The Bangla wording is mine; the owner reads it in E10.
