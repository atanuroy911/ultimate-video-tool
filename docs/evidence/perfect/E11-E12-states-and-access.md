# E11 and E12 - every state, and accessibility

## E11 - every page has every state
New `client/studio/e2e/states.mjs`: 12 pages (Your videos, New, editor, result, progress, script, export, Look, Server, Settings, short clips, Share) in four forced states each: loading (the API never answers), empty (the server's own answers with every list emptied), error (every call answers 500) and unreachable (every call is refused). For each it checks that readable text is on the page, no raw error or code shows (`Failed to fetch`, `Internal Server Error`, `undefined`, stack text...), the page did not crash, and no spinner is left running. Screenshots in `client/studio/e2e/out/states/` (viewed). Result: 180 of 180. At the start it was 168 of 180 plus a blank white page; what it found and what was fixed:
- Any answer in an unexpected shape could blank the whole app (the system pill read `gpus.find` of nothing). A missing or odd reading is now treated like no answer, and a new error boundary (`components/ErrorBoundary.tsx`) shows "Something went wrong on this page" with Reload and Your videos instead of a white page.
- Raw words reached the screen: "Failed to fetch" and "Internal Server Error". `api.ts` now says "The server did not answer. Check that it is running and that this computer can reach it." and "The server hit a problem (error 500). Try again; if it keeps happening, look at Details."
- The progress page showed a spinner for ever when the video could not be read; it now says "Could not open this video" with Try again and Your videos. The editor's loading text says "Opening your video…".

## E12 - accessibility
- `e2e/a11y.mjs` (axe-core 4.10.2 installed in a temp folder) now covers 13 screens (added script, progress, server, look): light and dark, 1440 and 390 wide. Found two serious contrast failures, fixed: the light-mode green (`--ok` 4.36:1 on the pale panel, now #166534) and the Server page's job state chips (hard-coded colours, now the tokens). Result: no serious or critical problem in all four modes. Only "heading-order" (moderate) remains, on 14 screens.
- New `e2e/keyboard.mjs` (16 checks): the New page from a script to Make my video by keyboard only, Settings by Tab, Escape closing a choice, visible focus at every stop, and with reduced motion nothing loops for ever. It found that arrow keys did not move between choices in radio groups; `radioKeys.ts` (installed in the Shell) now moves and picks with the arrow keys in every radio group (a control that handles keys itself is left alone).
