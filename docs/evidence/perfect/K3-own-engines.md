# K3: the engines Video Tool runs itself follow the cards, and the ones it does not run are reported

## What changed
- **Two more jobs** in `gpuassign.JOBS`: `ai` (Video Tool's own Ollama) and `pictures` (its own ComfyUI). They apply only to copies Video Tool started itself. They appear in `describe()["jobs"]`, in `vt gpu set <job> <card>` and in the MCP tool, and they are reset to "primary" when their card stops being allowed.
- **Start on the job's card.** `llm.start_server` and `ComfyInstaller.start` now pin the engine to the card its job resolves to (`gpuassign.job_env`: only that card visible; `-1` when cards exist and none is allowed, so it runs on the processor; nothing when there is no NVIDIA card). `ComfyInstaller.start` no longer uses the card a new install was built for (`setup_gpu`). `placement.start` passes our Ollama its program folder and model folder (`placement.own_dirs()`, the same two the installer uses), so it does not pick up whatever `ollama` is first on the path.
- **Restart when the card changes.** `gpuassign.change(patch)` is the one function behind the Server page (`PUT /api/system/gpu`), `vt gpu allow/set` and the MCP tool: it saves, and if the save moved a running copy of our own Ollama or ComfyUI to another card, restarts exactly that copy there (background for the server, finished for the command line). `engines/pids.py` records the process number and port of each copy we start, and stops one only while its command line still names the program (and, for ComfyUI, the port we gave it), so a number the computer has reused, or an Ollama or ComfyUI the person runs themselves, is never touched.
- **Say where the engines run.** `engines/where.py` gives `describe()["engines"]`: for Ollama and ComfyUI, whether it is Video Tool's own copy, one that was already running, one on another computer, or off; the cards it holds (from the cards' process lists, our own copy told apart by its recorded process number); a `code` and one plain English sentence. An engine that was already running on a card Video Tool may not use gets `offer_own`, and the sentence says what Video Tool does and does not do about it. `POST /api/system/engine-own`, `vt gpu own <engine>` and the MCP tool's `use_own_copy_of` point the pipeline at Video Tool's own copy and start it (in the background) on its job's card; the one that was there is left exactly as it is. It refuses with a sentence when the own copy is not installed.
- **The Server page** (`GpuAssignment.tsx`): the "Separate programs" line is now "Programs Video Tool works with": each engine with its sentence and, when offered, the button "Use Video Tool's own copy" (or, when it is not installed, where to install it). The status line tells a screen reader what started or restarted. Buttons are a finger tall on a phone.

## Found on the way
- `docs/ops/comfyui-server.md` said the owner's own ComfyUI service (port 8188) uses the V100 (`CUDA_VISIBLE_DEVICES=0`), and I repeated it here and in K2 and the breaking list. **That was wrong for today:** read on the server on 2026-11-06 (K6), the service's drop-in is `CUDA_VISIBLE_DEVICES=1` with `CUDA_DEVICE_ORDER=PCI_BUS_ID`, its `/system_stats` says "NVIDIA GeForce RTX 3060", and the card listing shows its python on the RTX 3060 (the V100 holds 9 MiB). The old document was out of date and is corrected. Video Tool does not change that service either way; the Server page says where an engine that was already running sits, in the words above.
